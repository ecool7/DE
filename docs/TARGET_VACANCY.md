Ты целишься в роль **Data Engineer с мышлением Data QA**: не только «собрал пайплайн», но и **доказал качество данных** (тесты, мониторинг, ревью, доки).

## Красная нить: Data QA

На каждой витрине/ETL спрашивай себя:

1. **Schema** — колонки и типы как в контракте?  
2. **Integrity** — PK уникален? FK на клиента/счёт живой?  
3. **Freshness** — данные за нужный `business_dt`? нет ли «застывшего» среза?  
4. **Quality** — null-rate, дубли, выбросы по сумме?  
5. **Accuracy** — бизнес-правило верно? (пример: NPL = просрочка ≥ 90 дней)

Пока нет ответа — **в prod не релизим**.

## Стенды (уже в проекте)

```
работаешь в TEST → гоняешь тесты → release_to_prod → смотришь PROD в Ops Console
```

Это ровно то, что в вакансии звучит как «внедрение» и ответственность за качество до потребителей (аналитики / DS).
